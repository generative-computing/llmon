Labeling Guidelines

Reference for the 9 span classes — what each one means, what it looks like highlighted, and general labeling conventions.
  • To label a span, highlight (select) the text with your mouse — a class picker will appear, letting you assign it a label.
  • Label every word in the text — every word should fall under at least one span. This means covering every word, not necessarily every character: trailing punctuation and whitespace between spans are intentionally left unlabeled (see Trailing punctuation below).
  • Once you've finished labeling an entry, mark it as complete so you can keep track of your progress through the file.
No autosave
The labeler does not save anything automatically. All your work lives only in the browser tab's memory. The only way to keep it is clicking Export — closing the tab, refreshing, or navigating away without exporting first will lose all progress.

General rules

Nesting vs. intersecting

Spans can exist within other spans (a subset relationship — one span's range fully contains another's). This is common and expected. What you should avoid is two spans that intersect — where they partially overlap but neither fully contains the other. The examples below use stacked underlines (one bar per class) instead of solid fills, the same way the labeler itself renders overlapping spans — so you can see every class that applies to a given stretch of text at once, rather than one color hiding another.
Your answer must contain a title, wrapped in double angular brackets, such as <<my title>>.
Good — nesting. such as <<my title>> carries both underlines (Output Format + Example) because the Example span sits entirely inside the Output Format span, which covers the whole requirement. (Real example, ifeval_2683)
Avoid — real mislabel, ifeval_2195
Write a list of instructions for a dog trainer to teach a dog to sit, stay, and fetch. Your list should contain exactly 3 bullet points in the markdown format such as:
* Bullet point 1
* Bullet point 2

Only the word "such as:" carries both underlines — that's the overlap zone. Before it, only Output Format's underline shows; after it, only Example's does. Neither span's range contains the other, which is exactly the problem: the boundary where one ends and the other begins is staggered instead of aligned or nested. Fix: either end Output Format right before "such as:" so Example starts cleanly after it, or extend Output Format to fully contain the Example span.

Trailing punctuation

Don't include trailing punctuation in a span unless it's a question mark, or the punctuation is important to the span's meaning (e.g. a quotation mark that's part of quoted text, or a colon introducing a list/example that belongs with it).
Can you give me a nickname for Stafford?
Good — the question mark is kept because the span is a question. (Real example, ifeval_2880)
Aim the blog post at teenagers.
Good — the trailing period is left out of the span.

Branching / conditional instructions

When a prompt branches with "if / otherwise" logic, label the whole conditional block (the full "if X, do Y, otherwise do Z" unit) as Instruction — it's still telling the model what action to take, just with a condition attached. The condition itself, the "Otherwise" branch, and any specific requirements (word/character counts, required prefixes) nest inside as Constraint and Output Format.
Evaluate the following sales copy. - If the copy is for flower sales, and it is descriptive copy (i.e., straightforward advertising copy), rewrite it as a story-based copy, with around 100 characters, beginning with "Flower World". Otherwise, shorten it to one sentence. - If the copy is not for flower sales, and it is story-based copy (i.e., the advertisement is embedded in an attention-grabbing story), adapt the storyline to rewrite it as a flower sales copy with around 150 characters. Otherwise, shorten it to two sentences.
Real labels from complex_1010. Each full if/otherwise branch is one Instruction span. The condition and the "Otherwise" marker are Constraint; the resulting output shape (character count, sentence count, required prefix) is Output Format.
Avoid
Labeling the condition and action as two unrelated top-level spans (e.g. a standalone Constraint next to a separate, disconnected Instruction). Keep the whole conditional-plus-action unit as one Instruction span, with the condition/otherwise/shape nested inside it — splitting them apart loses the fact that the condition only matters because of the action it gates.

The 9 classes

Instruction

Spans that describe an action the model must perform — the core verb-driven task. Includes direct imperatives ("Write...", "Explain...", "Summarize...") and polite/indirect requests ("Can you...", "I want you to...").
Write a blog post about the history of the internet and how it has impacted our lives. Aim the blog post at teenagers.
Real example, ifeval_122.
More examples

Write a limerick about Hannah, a college student, doing an internship at a coffee company — ifeval_1281

Constraint

Spans that describe how a task should be carried out — a limitation, requirement, or condition on the instruction (length, tone, required/forbidden words, audience, language). Doesn't describe the shape of the final output (that's Output Format) — describes a rule the process/content must follow.
Write a limerick about Hannah, a college student, doing an internship at a coffee company. Make sure that her father would love the limerick. Include the words "intern" and "grow".
Real example, ifeval_1180-style.
More examples

Output Format

Spans that describe how the output itself should look — structure, wrapping, delimiters, markdown, word/paragraph counts tied to presentation, required titles/headers.
There should be exactly 3 paragraphs separated by the markdown divider: ***
Real example, ifeval_1236.
More examples

Content

General, purely declarative information the model needs to work with — that isn't itself an instruction, constraint, output rule, or framing/context about the prompt. Look for statements of fact or subject matter with no directive, question, or "here's what's coming" framing attached — if a span reads like it could be its own instruction or question in isolation, it's probably not Content. This also covers text in a different language than the surrounding prompt: if it's not directly part of an Instruction, Constraint, or Output Format span (e.g. it's the subject matter to translate, summarize, or otherwise work with), label it Content.
Write a short response to the following claim, and explain whether you agree. Textbooks are regarded as the sole model for subject teaching in the school education of all developed countries.
Real span from complex_689. A flat factual/opinion statement serving as subject matter — not a question, not an instruction, not framing.
More examples

Structured Data

Multiple-choice options, numbered/lettered lists, tables, or other clearly delimited data — only when it isn't better explained by Instruction, Constraint, or Output Format. If a numbered list is itself the required output shape, that's Output Format instead.
In the World Table Tennis Championships, the men's team championship trophy is called ( ) A Iran Cup B Pop Cup C Corbillon Cup D Swaythling Cup
Real example — multiple-choice answer options.

Quoted Content

Most commonly, text wrapped in triple double-quotes (""") — this is the most frequent form. Everything inside the fence is Quoted Content as a single span, regardless of what's inside it (it could contain instructions, examples, data — doesn't matter, the fence takes priority). Single/double quotation marks (' ' or " ") around a shorter piece of literal text the model must treat as a fixed blob — e.g. a sentence it's asked to elaborate on or finish verbatim — also count as Quoted Content, just less commonly than the """ fence.
Rewrite the following text: """ The quarterly report shows revenue increased by 12% year over year... """
Everything between the """ fences is one Quoted Content span, no matter what's inside.
"A gymnast is in the air, performing a stunt."
Real example, ifeval_2909 — a quoted sentence the model is asked to elaborate on.

Example

A template, sample, or demonstration of what the output's structure/format should look like — almost always nested inside a larger Output Format span (see the Output Format example above). This is not a general-purpose label for any "e.g." or "for example" in a prompt — an illustrative example used to clarify a point in ordinary prose (e.g. "such as dogs and cats" inside a sentence of Content) is just part of that surrounding span, not its own Example label. Reserve Example specifically for output-shape demonstrations: placeholder syntax, markdown formatting samples, template skeletons.
Make sure your blog post contains at least 7 placeholders represented by square brackets, such as [location]
Real example, ifeval_1372.

Context

Spans that frame or introduce what's present elsewhere in the prompt, without being the instruction/content itself — headers like "Background:" or "Requirements:", scene-setting asides ("I am very excited about..."), or a stated premise the rest of the prompt builds on.
Given that the French Revolution began because the French King tried to tax the people of France, explain why the revolution escalated into a broader European conflict.
Real example — sets up a premise the Instruction depends on, but isn't the instruction or the subject content itself.

Quick checklist

  • Would this span make sense read completely on its own? If it's chopped mid-clause, extend it.
  • Nested spans: fine. Intersecting spans (partial overlap, neither contains the other): not fine — adjust a boundary.
  • Trailing punctuation: drop it, unless it's a ? or it's semantically load-bearing (closing quote, colon before a list it introduces).
  • Conditional/branching instructions: label the whole if/otherwise unit as Instruction; only the specific requirements nested inside as Constraint.
  • """-fenced blocks (most common) are always one Quoted Content span end-to-end, regardless of what's inside. Single/double-quoted literal text the model must treat verbatim is also Quoted Content, just less common.
  • When unsure between Structured Data and Output Format for a list: if the list is itself what the model must produce, it's Output Format; if it's given data the model is reading, it's Structured Data.
